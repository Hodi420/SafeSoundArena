# STP — תוכנית בדיקות RC-0

מסמך `SSA-RC0-STP-v1` · 2026-08-27 · [אינדקס ההגשה](README.md).

**סטטוס: טיוטה לסקירה.** זהו תיעוד רטרוספקטיבי של היקף היחידה שכבר הורץ, ותכנון לבדיקות ההמשך. אין טענה שהמסמך הזה אושר לפני ההרצה, ואין ממנו אישור אוטומטי לבצע את הבדיקות המתוכננות.

## מטרה ובסיס הבדיקה

להפריד בין תקינות ליבה מוגבלת שהוכחה לבין מוכנות מערכת ושחרור שטרם הוכחו. בסיס הקוד: `e33cfd88d127c5e7cd1a7266295aa924b9935b3b`; מקור ביצוע: `rc0-20260827-01`.

המקורות הם [Operational Input Spec](../../../OPERATIONAL_INPUT_SPEC.md), [Operational Handoff](../../OPERATIONAL_HANDOFF.md), [MSHIX Core Spec](../../MSHIX_CORE_SPEC.md), היקף [SSA-2](https://app.notion.com/p/3c93b4e496d781008439cdf0220e3e7a) וראיות E01–E10. נתוני 19 באוגוסט אינם אימות חוזר של הגרסה הנוכחית.

## היקף ושיטת בדיקה

| שכבה | שיטה | מצב |
| --- | --- | --- |
| יחידה/אחסון נבחרים | 10 קובצי Mocha, 46 מקרי בדיקה שעשויים להכיל מספר assertions, fixtures זמניים, providers מדומים | בוצע; PASS_BOUNDED |
| תצורה ובידוד של ההרצה | manifest/hash, preflight של הקונטיינר ובדיקת isolation בתוך התהליך | ראיות ב־E02–E05; אינן חוזה רשת של האפליקציה |
| API + Frontend מבודדים | תרחישי SYS-01–SYS-08 ב־STD, חיוביים ושליליים | NOT_RUN; תנאי הכניסה טרם הושלמו |
| build, CI, מסירה ו־post-deploy | תרחישי REL-01–REL-04 | NOT_RUN; שלבי שחרור עתידיים |

ארבע בדיקות Feature Store אינן בדיקות של ששת ה־HTTP APIs: הן בודקות אירועים, התקדמות quest, שגיאות marketplace ושמירה/טעינה של fixture. בפרט אין כאן אימות HTTP של Notifications או Challenges. בדיקות Brain משתמשות בספקים מדומים; בדיקות PQS הן simulation/proof ולא משחק HTTP או אינטגרציה רשמית.

מחוץ להרצה שבוצעה: full root/frontend suites, typecheck/build, listeners, application entrypoint, API/UI, Socket.IO, CI, Ollama אמיתי, restore של שירות, load/performance/accessibility/browser matrix, deployment ואינטגרציות חיצוניות. פריט מוחרג מהרצה זו אינו מוחרג אוטומטית משחרור עתידי.

## סביבת ההרצה שבוצעה — G1

- Node `v24.19.0`, UID/GID `65534:65534`; 19 קובצי מימוש ו־10 קובצי בדיקה מה־allowlist בלבד.
- קונטיינר ללא רשת חיצונית, published ports, bind mounts או volumes. ממשק `lo` בלבד, rootfs וקלט לקריאה בלבד, `/app` של image הבסיס מוסתר ב־tmpfs ריק.
- כתיבות fixtures ב־`/tmp` זמני בזיכרון; תלויות Mocha/Express קיימות בלבד. לא בוצעו install, pull או הורדת מודלים.
- CPU אחד, 512MiB, 64 pids, capabilities מוסרות, no-new-privileges, healthcheck/restart כבויים, deadline חיצוני 45 שניות.
- ה־image המקומי הנגזר ומשאבי הבדיקה כבר הוסרו. סביבת G1 אינה סביבת אפליקציה פעילה או artifact למסירה.

התצורה המדויקת והראיות ב־[STR](STR.md) וב־[manifest](EVIDENCE_MANIFEST.json). סקריפטי `stage.cjs` ו־`control.cjs` חד־פעמיים, עם מזהים ונתיבים של הרצה שהסתיימה. הרצה חדשה דורשת preflight ומזהים חדשים; אין להריצם כפי שהם.

## נתוני בדיקה וסביבה מתוכננת ל־G2

ה־API וה־Frontend יופעלו רק בעותק נפרד לאחר preflight. לא ייבחרו כעת פורטים חדשים ולא ינוצלו שירותי המשתמש הקיימים ב־3000/4000/5001/8080. ב־run record העתידי חייבים להיות ערכים מדויקים ל־`WEB_ORIGIN`, `API_INTERNAL_URL`, Socket origin אם נדרש, image/source/config hashes ונתיבי state ייעודיים. אלה שדות תכנון, לא environment variables קיימים שיש להזריק אוטומטית.

מערך נתונים מוצע: משתמשי דמה `qa-user-a` ו־`qa-user-b`, תפקיד admin בדיקה, event/guild/item/quest/challenge IDs שהתקבלו מה־fixture בפועל. אין להניח שה־seed הקיים מכיל IDs אלה. כל testcase יוצר או מאתר fixture מורשה ורושם אותו בלי PII.

Credentials סינתטיים ייווצרו רק בתוך סביבת הבדיקה המורשית; ערכיהם לא יופיעו במסמכים, לוגים, screenshots או `NEXT_PUBLIC_*`. אין להפוך `X-User-Id` לזהות מאומתת ואין להעביר token ניהולי גלובלי לדפדפן כפתרון לחיבור UI.

## תנאי כניסה ל־G2 — כולם נדרשים

- [ ] נבחרו תרחישים, endpoints, גרסת קוד וקריטריוני expected מפורשים; החלטות Auth שטרם נבחרו מסומנות כממתינות ל־SSA-3.
- [ ] הוכח שכל state, audit, MCP permissions, outbox ו־Brain שייכים לנתוני הבדיקה; אין טעינת `.env` או state קיים דרך build context, שכבות image או default paths.
- [ ] כל שירות/volume/image נושא מזהה ייחודי ומתועד; שירותי המשתמש נשארים מחוץ להקמה, לבדיקה ול־cleanup.
- [ ] חוזה רשת כולל IPv4/IPv6, binds, CORS, כתובת דפדפן ו־Next `/api`; קיימת חסימת יציאה טכנית, ולא רק loopback או דגלי PQS.
- [ ] `/api/pi-auth`, ספקי AI, telemetry, model fallback ו־IPFS לא יכולים לצאת לשירות חיצוני לא מאושר. probe לחסימה נעשה ל־sink מדומה/מבודד בלבד.
- [ ] restore, replay, lease monitors ו־Jail scheduler לא יכולים לשנות נתונים קיימים; לכל background action יש תחום זמן ונתונים ידוע.
- [ ] קיימים deadline, stop condition, רשימת משאבים בבעלות ההרצה ודרך לשמור ראיות ללא סודות.

אי־עמידה בתנאי כניסה משאירה G2 לא מורץ. אין להשתמש בהחלשת auth, התחברות לנתוני אמת או הרחבת חשיפה כדי להשלים את הבדיקה.

**G1 — היחידה שבוצעה:** בדיוק 46 בדיקות, 46 עברו, 0 failures/pending, exit 0, 0 ניסיונות רשת/listener/subprocess שזוהו, זיהוי מקור ובידוד. התנאים התקיימו בהיקף הראיות; אין מכך התחייבות לתפקוד המערכת.

**G2 — אימות מערכת מקומי:** לכל מופע תרחיש שנבחר יש expected/actual/evidence; כל תרחיש חובה עבר, או שההיקף שונה במפורש לפני קבלה. בדיקת חובה NOT_RUN/BLOCKED, כשל בידוד או הפרת הרשאה מונעים קבלה. נשמר דוח והניקוי מוגבל למשאבים המזוהים.

**G3 — שחרור:** אותו candidate SHA/artifact בכל הראיות; כל דרישות החובה מכוסות בתוצאות על אותה גרסה; required remote checks ירוקים; אין release blockers; runbook ותרגול recovery מתאימים ליעד; החלטת Go של בעל הסמכות. תנאי אבטחה ונתוני אמת אינם ניתנים להחרגה כדי לעקוף כשל. כיום G3 הוא NO_GO.

## כללי תוצאה, עצירה והמשך

| ערך | משמעות |
| --- | --- |
| PASS | הבדיקה בוצעה על גרסה מזוהה וכל ה־assertions שהוגדרו עברו, עם ראיה |
| FAIL | בוצעה בדיקה והתקבלה סטייה מהצפוי; מצורפים actual וממצא |
| BLOCKED | לא ניתן להשלים ביצוע בגלל תנאי כניסה/סביבה מוגדר; מצורפים סיבה, owner ופעולת שחרור החסם |
| NOT_RUN | לא בוצע התרחיש; תכנון, קריאת קוד או היסטוריה אינם הרצה |
| N/A_APPROVED | לא חל על ההיקף המאושר, עם נימוק, מאשר ותאריך; אינו PASS |

סטטוס ביצוע וסטטוס משימת Notion הם שני שדות שונים. לכל תרחישי ההמשך במסמך STD יש כרגע NOT_RUN; תנאי הכניסה החסרים רשומים בנפרד. אין להוסיף אותם למכנה של 46 בדיקות היחידה או להסיק אחוז כיסוי מהתוצאה.

עוצרים על חשיפה לא צפויה, יציאה חיצונית לא מאושרת, קריאת נתון/סוד קיים, הפרת הרשאה או חריגת זמן. שומרים ראיה מצונזרת ועוצרים רק משאב הרשום בבעלות ההרצה. לא מפעילים reset, prune, מחיקת volumes או שינוי Firewall/Docker כפתרון. חזרה לביצוע מחייבת תיקון סיבת העצירה, preflight חדש וקישור להרצה החדשה.
